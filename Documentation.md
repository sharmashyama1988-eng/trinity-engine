# 📖 Trinity Engine Technical Documentation v2.1

## 1. Introduction
Trinity Engine is built on a hybrid architecture combining **Python's high-level flexibility** with **C++ native execution speed**. This document explains how the internal modules interact with the Windows Operating System.

## 2. XEngine Architecture
The XEngine uses a dual-layer search strategy:
- **Layer 1 (Python Fallback):** Uses `os.scandir` and `threading` to index files recursively without external dependencies.
- **Layer 2 (Native Core):** A C++ DLL (`XEngine.dll`) that utilizes Win32 `FindFirstFile/FindNextFile` APIs for direct NTFS interaction.

## 3. God Mode & Kernel Interaction
The `GodMode` module utilizes `ctypes` to invoke `ntdll.dll` and `kernel32.dll` functions.
- **SetProcessWorkingSetSize:** Used to force applications to release unused RAM.
- **SetPriorityClass:** Dynamically boosts the CPU priority of the active foreground window.
- **Shell Replacement:** Modifies `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Policies\System` to point the `Shell` key to TrinityEngine.

## 4. Smooth Engine (Stealth Optimization)
The **Smooth Engine** is a background monitor. It runs in a separate thread/process and polls the `GetForegroundWindow` API every 500ms. If the active process is not optimized, it applies the **Trinity Priority Profile** to ensure zero-lag input and rendering.

## 5. Hardware Adaptation Bridge
The `AdaptationBridge` profiles the system using `psutil` and `WMI`.
- **Light Tier:** < 8GB RAM, < 4 Cores. Optimization frequency is reduced to save battery.
- **Extreme Tier:** > 16GB RAM, 8+ Cores. Full persistent optimization and aggressive cache flushing enabled.

## 6. Security & Stability
- **Single-Instance Lock:** Uses a local socket on port `45712` to prevent multiple engine instances from conflicting.
- **Auto-Admin Elevation:** Uses `ShellExecuteW` with the `runas` verb to ensure the engine has the necessary handles to system processes.
